### 2. CircularDetector误判Bug

**问题描述**：
- 修复前：`"碳排放权交易管理办法规定..." in "...按照碳排放权交易管理办法执行"` → 误判为循环
- 原因：简单使用Python的`in`运算符判断包含关系，太宽松

**修复方案**：
```python
def _is_circular_pair(self, sent1: str, sent2: str) -> bool:
    # 1. 完全相同 → 循环
    if sent1 == sent2:
        return True
    # 2. 字符重叠>95% → 重复
    overlap = len(chars1 & chars2) / max(len(chars1), len(chars2), 1)
    if overlap > 0.95:
        return True
    # 3. "因为"分隔的因果互换 → 循环
    # A是因为B支持A，B是因为A支持B
```

**教训**：
1. 字符串包含检测（`in`）在中文文本上容易误判，因为中文共享常用字
2. 边界条件测试必须写：正常引用、真正循环、完全重复、短文本
3. 写完功能马上跑4个基础测试场景验证

## 二、开发规范（铁律）

### 测试覆盖率规范

| 模块类型 | 最低覆盖率 | 强制要求 |
|----------|-----------|----------|
| 核心模块（delta_s/kun_guard等） | ≥90% | 必须全路径覆盖 |
| 检测器（rule/hallucination等） | ≥85% | 每个方法都有测试 |
| 新增模块 | 100%起步 | 随功能扩展可降但不低于85% |
| 治理层（governance） | ≥85% | 每个门类型都要测 |

### 测试场景规范

每个模块必须有：
1. **正向测试**：正常输入 → 预期输出
2. **负向测试**：异常输入 → 正确报错
3. **边界测试**：空输入、超长输入、None值
4. **误判测试**：容易误判的案例（针对检测器）

### 代码质量规范

- [ ] `ruff check src/` 零错误
- [ ] `ruff format src/` 格式化
- [ ] `mypy src/ --ignore-missing-imports` 无致命错误
- [ ] 禁止 `# type: ignore` 滥用
- [ ] 禁止 `Any` 类型滥用
- [ ] 禁止行内 `import`（放在文件头部）

## 六、关键经验

1. **覆盖率不是平均分**：短板模块会拖垮生产稳定性
2. **中文文本检测要谨慎**：共享常用字≠循环论证
3. **测试先行**：不要写完代码再补测试，习惯从一开始就覆盖
4. **误判测试同等重要**：漏掉误判比漏掉正常检测更危险
5. **每次commit前自检**：不要把问题留给CEO发现
